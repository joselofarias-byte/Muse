## Otras mejoras importantes detectadas

Estos son hallazgos adicionales, **no promesas de incorporación**. Si se difieren, no son defectos creados por la selección; quedan identificados para una corrección separada y comprobable:

- `678ffb82`: base contiene cinco filtros de conexión MCP que exigen URL incluso para STDIO. Portar `isConnectable()` según transporte y sus pruebas es una corrección pequeña sin ampliación funcional.
- `cdddf004`: `HtmlPreviewScreen` de base llama `WebStorage.deleteAllData()` al desmontar. Eso afecta datos globales del navegador, no solo la tarjeta. Portar limpieza local y no el guardado global de cookies/sitios. Guardas posteriores `5e77ad58`/`41bc88bf` son CI, no requisito del arreglo Android.
- `59d06de8`: la marca Safe Mode anterior se decide por existencia y borrar puede devolver false; fallback al contenido `0` evita quedar atrapado. Útil junto a cierre seguro, pero semánticamente independiente.
- `0375cb2c` → `a7ecd450` → `fe1708c8` y `cdc9f5ac`: mejoras de redacción de logs, en particular credenciales multipartes y tokens Telegram en el **path** de URL. No registrar un Throwable sin asegurar que todas las salidas pasan redacción: sanear solo el texto del mensaje no protege el stacktrace.
- `60747bd2`: comparación de directorios debe exigir separador para no aceptar rutas hermanas. Parte de la superficie pertenece a paquetes skill nuevos; portar solo rutas existentes y pruebas, no toda la función skill.
- `0cee96b0`: respeto del interruptor global de plugins en comandos/paneles; depende de superficies plugin nuevas. No añadir esas superficies solo para aplicar su corrección.
- Los fixes de web host/cliente (`46d76755`, `5c70154e`, `d03de8e5`, `c89461cb` y pendientes de cliente) deben tratarse como unidad de protocolo si se habilita ese producto, no como prerrequisito del relay Android.
